데이터베이스와 DBMS

SQLD 입문을 위한 핵심 개념 정리

1 데이터 → DB → DBMS

데이터(Data)

개별적인 사실이나 정보
1001 ``` 홍길동 개발팀 5000
```

위와 같은 개별적인 값이나 사실 자체는 데이터이다.

데이터베이스(Database, DB)

데이터를 일정한 구조와 규칙에 따라 체계적으로 저장해 놓은 데이터의 집합

즉, DB는 단순히 데이터 하나를 의미하는 것이 아니라 관련된 데이터들이 일정한 구조를 가지고 모여 있는 것으로 이해할 수 있다.

DBMS

2 Excel과 DBMS의 차이

Excel 역시 데이터를 체계적으로 관리하는 데 사용할 수 있다.

사번 | 이름 | 부서 | 급여 ``` --- 001 | 김철수 | 개발팀 | 4000 002 | 이영희 | 기획팀 | 3800
```

하지만 Excel에서는 사용자가 정한 규칙을 사람이 지키면서 사용하는 것이 중요한 부분이다.

핵심 관점
Excel과 DBMS의 차이를 단순히 "체계적으로 관리할 수 있느냐 없느냐"로 보는 것보다, "그 체계를 누가 관리하고 강제하느냐"로 보는 것이 중요하다.

Excel에도 데이터 유효성 검사, 셀 보호 등의 기능을 이용하여 일정한 규칙을 적용할 수 있다.

그러나 DBMS에서는 데이터 구조와 제약조건을 시스템에 정의하고 DBMS가 이를 관리·강제할 수 있다.

3 DBMS가 관리하는 "체계"

① 테이블 이름

일반적으로 동일한 데이터베이스/스키마 안에서는 동일한 이름의 테이블을 여러 개 만들 수 없다.

학생 ``` 학생 학생 → 동일한 이름의 테이블을 여러 개 생성할 수 없음
```

② PRIMARY KEY

PRIMARY KEY로 지정된 컬럼 또는 컬럼 조합은 중복된 값을 가질 수 없다.

CREATE TABLE 학생 ( 학번 INT PRIMARY KEY, 이름 VARCHAR(20) ``` );
```
INSERT INTO 학생 VALUES (1, '김철수'); ``` INSERT INTO 학생 VALUES (1, '이영희');
```

두 번째 입력은 PRIMARY KEY 제약조건에 의해 DBMS가 거부한다.

사람이 "중복하지 말자"고 약속하는 것과
DBMS가 "중복을 허용하지 않는다"고 강제하는 것은 다르다.

4 "엑셀은 DB인가요?"

이 질문은 엄밀하게 보면 개념의 층위가 서로 다르기 때문에 애매한 질문이다.

개념 의미
DB 체계적으로 구성된 데이터의 집합
DBMS DB를 관리하는 소프트웨어
Excel 데이터를 다루는 스프레드시트 프로그램
따라서 "엑셀은 DB인가요?"보다는
"엑셀은 DBMS인가요?"라고 질문하는 것이 개념적으로 더 적절하다.

Excel은 데이터를 저장하고 관리할 수 있지만, SQLD에서 말하는 전형적인 관계형 DBMS와는 다른 프로그램이다.

5 왜 "DB"가 헷갈리는가?

실무에서는 "DB"라는 말을 엄밀한 의미보다 넓은 의미로 사용하는 경우가 많다.

"DB에 데이터 넣었어?"
→ 데이터베이스를 의미하는 경우
"DB 뭐 써요?"
→ MySQL, Oracle 등의 DBMS 또는 DB 제품을 의미하는 경우
"DB 서버 죽었어요."
→ DBMS가 동작하는 서버를 의미하는 경우

따라서 실무에서는 문맥에 따라 DB, DBMS, DB 서버, DB 제품 등을 "DB"라고 뭉뚱그려 표현하는 경우가 있다.

SQLD에서는 의식적으로 구분하자.

실무에서는 "DB"라는 말을 넓게 사용할 수 있지만, SQLD에서는 DB와 DBMS를 구분해서 사용한다.

한 문장으로 정리

데이터는 개별적인 사실·정보이고, DB는 그런 데이터를 일정한 구조와 규칙에 따라 체계적으로 모아 놓은 것이며, DBMS는 그 DB를 관리하는 소프트웨어다.

실무에서는 이 셋을 엄밀하게 구분하지 않고 "DB"라는 말을 넓게 사용하는 경우가 있기 때문에 혼동하기 쉽다.
