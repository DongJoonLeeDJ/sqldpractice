⭐ 시험 포인트

Relation / Tuple / Attribute / Domain 용어 문제는 매우 자주 출제된다.

  • Relation
    • 데이터를 표 형태로 표현한 것(테이블)
    • 서로 관련된 데이터를 하나의 표 구조로 묶어 표현한 것
    • 속성과 속성값으로 구성된 2차원 데이터 구조(테이블)
    • 관계형 모델에서 Relation은 수학의 '관계(Relation)' 개념에서 나온 용어이며, 데이터를 행과 열의 2차원 구조로 표현한다.
  • Tuple: Relation을 구성하는 하나의 행(Row)
  • Attribute: Relation을 구성하는 하나의 열(Column)
  • Domain: Attribute가 가질 수 있는 값들의 집합
    
## Relation / Tuple / Attribute / Domain

학생 테이블을 예로 들어보자.

| 학번   | 이름  | 학년 |
| ---- | --- | -- |
| 1001 | 김철수 | 2  |
| 1002 | 이영희 | 3  |

### ① Relation (릴레이션)

* 데이터를 **표 형태로 표현한 것**
* 쉽게 말해 **테이블**
* 예: `학생` 테이블

### ② Tuple (튜플)

* Relation에서 **하나의 행(Row)**
* 한 명의 학생에 대한 전체 데이터
* 예: `(1001, 김철수, 2)`

### ③ Attribute (속성)

* Relation에서 **하나의 열(Column)**
* 데이터를 어떤 기준으로 구분할 것인지 나타냄
* 예: `학번`, `이름`, `학년`

### ④ Domain (도메인)

* 하나의 Attribute가 **가질 수 있는 값의 범위**
* 예: `학년`의 Domain → `1, 2, 3, 4`
* 예: `성별`의 Domain → `남, 여`

### ⭐ 한 줄 암기

* Relation = **테이블**
* Tuple = **행(Row)**
* Attribute = **열(Column)**
* Domain = **속성이 가질 수 있는 값의 범위**

### ⭐ 쉽게 비유하면

학생 테이블에서

`학년` → Attribute
`1, 2, 3, 4` → Domain
`1001, 김철수, 2` → Tuple
`학생 테이블 전체` → Relation






    쉽게 말하면 Domain(도메인) = 어떤 속성(Attribute)이 가질 수 있는 값의 범위야.

예를 들어 학생 테이블이 있다고 하면:

학번	이름	학년	성별
1001	김철수	2	남
1002	이영희	3	여

각 Attribute의 Domain은:

학번 → 숫자 형태의 학번
이름 → 문자열
학년 → 1, 2, 3, 4
성별 → 남, 여

즉,

Attribute = 무엇을 저장할 것인가

Domain = 그 Attribute에 어떤 값들이 들어갈 수 있는가

SQLD식으로 외우면

Domain = 속성이 가질 수 있는 원자값들의 범위

예를 들어 학년이라는 Attribute의 Domain이 {1, 2, 3, 4}라면

학년 = 2 → 가능
학년 = 4 → 가능
학년 = 7 → ❌ Domain을 벗어남
Relation / Tuple / Attribute / Domain 한 번에
학생 Relation(테이블)
│
├── Attribute(열)
│     ├── 학번
│     ├── 이름
│     └── 학년
│
├── Tuple(행)
│     └── (1001, 김철수, 2)
│
└── Domain
      ├── 학번 → 가능한 학번 값들의 범위
      ├── 이름 → 가능한 문자열 값들의 범위
      └── 학년 → {1, 2, 3, 4}

시험에서는 특히 Domain = 속성이 가질 수 있는 값의 집합/범위라고 기억하면 충분해.

그리고 헷갈리기 쉬운 게 Attribute와 Domain의 차이인데,

학년 = Attribute
1, 2, 3, 4 = Domain

이렇게 생각하면 거의 안 헷갈려.
