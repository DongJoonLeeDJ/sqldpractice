여러분. 지금까지는 학생 정보를 하나의 표에 저장했습니다.

그런데 질문 하나 드릴게요. 학생이 수강신청을 하면 과목 정보도 같은 표에 넣으면 될까요?

💬 예상 답변 - 너무 길어집니다. - 같은 학생 정보가 반복됩니다. - 관리하기 어려워집니다.

학생(Student) ---------------------------- 학번 이름 학과 ---------------------------- ↓ 수강(Enrollment) ---------------------------- 학번 과목코드 신청일 ----------------------------

💬 예상 답변 - 같은 학생을 찾기 위해 - 연결하기 위해 - 누구의 수강정보인지 알기 위해
🎤 강사 정답입니다. 바로 '연결' 하기 위해서입니다.
학생 ──────┐ 학번 ──────┘ │ ▼ 수강 학번 과목
🎤 강사 이렇게 여러 개의 테이블을 '관계(Relation)'로 연결해서 데이터를 관리하는 방식이 관계형 데이터베이스입니다.
⭐ SQLD 시험 포인트 관계형 데이터베이스는 테이블 간의 관계를 이용하여 데이터를 관리한다.

🎤 강사 여러분이 사용하는 쇼핑몰도 하나의 거대한 테이블이 아닙니다.

🧠 용어 정리

관계(Relation) ↓ Table ↓ 여러 Table이 공통된 값으로 연결된다.
🎤 강사 '관계형'이라는 말은 복잡한 철학적인 개념이 아닙니다. '테이블끼리 연결되어 있다.' 정도로 이해하면 오늘은 충분합니다.

관계형 데이터베이스 정리 및 Entity 예고

🎤 강사

자, 지금까지 내용을 한 문장으로 정리해보겠습니다.

파일로 관리하면 데이터가 중복되고 관리가 어려워집니다. 그래서 DBMS가 등장했습니다. 그리고 DBMS는 데이터를 표(Table) 형태로 관리합니다. 필요하면 여러 개의 표를 연결하여 사용합니다. 바로 이것이 관계형 데이터베이스입니다.
파일 ↓ 중복 ↓ DBMS ↓ Table ↓ Relation ↓ RDBMS

🎤 강사

Entity는 무엇을 가지고 있을까?

🎯 목표 학생들이 Attribute와 Instance를 암기하지 않고 직접 찾아낼 수 있도록 한다.
🎤 강사

방금 우리는 학생(Student)이 Entity라는 것을 알았습니다.

그런데... 학생이라는 말만 있으면 학생을 관리할 수 있을까요?
❓ 학생 참여 학생을 관리하려면 어떤 정보가 필요할까요?
절대 먼저 말하지 않는다. 학생들에게 20~30초 정도 생각할 시간을 준다. 학생들이 자유롭게 말하도록 유도한다.
💬 예상 답변 - 학번 - 이름 - 전화번호 - 학과 - 학년 - 이메일
🎤 강사 좋습니다. 여러분이 말한 것들이 학생을 설명하는 정보입니다. DB에서는 이런 정보를 '속성(Attribute)' 이라고 합니다.
학생 ↓ 학번 이름 학과 학년 전화번호 ↓ Attribute
★★★★★ Entity를 설명하는 정보 ↓ Attribute

✏️ 판서 예시

학생(Entity) ────────────────────── 학번 이름 학과 학년 ──────────────────────
🎤 강사 여기서 '학생'은 Entity, 각 항목은 Attribute입니다.

❓ Instance란?

🎤 강사 그럼 질문 하나 더 드리겠습니다.

학번이라는 속성에는 실제로 어떤 값이 들어갈까요?
학생들에게 실제 값을 말해보라고 한다.
💬 예상 답변 2026001 홍길동 컴퓨터공학과 1학년
학생 ────────────────────────────────── 학번 이름 학과 2026001 홍길동 컴퓨터 2026002 김철수 전자 2026003 이영희 경영 ──────────────────────────────────
🎤 강사 좋습니다. 이제는 '학생'이라는 개념이 아니라 실제로 저장된 데이터가 보이죠?

이렇게 실제 저장된 하나의 데이터를 Instance라고 합니다.
