13:20 ~ 13:30

학습 목표
  • 오늘 배운 내용을 하나의 흐름으로 연결한다.
  • 학생들이 데이터 모델링의 전체 과정을 경험한다.
  • Day2(식별자)로 자연스럽게 이어진다.

최종 실습

강사 오늘 배운 내용을 이용해서 학생(Entity)를 완성해 보겠습니다.
학생 ↓ Entity ──────────────────── 학번 이름 전화번호 학과 입학일 ↓ Attribute ──────────────────── 20260001 김철수 010-1234-5678 컴퓨터공학과 2026-03-02 ↓ Instance ──────────────────── 학번 : 숫자 8자리 전화번호 : 숫자와 '-' 형식 입학일 : 날짜 형식 ↓ Domain
학생들에게 질문한다.

"오늘 배운 개념 중 하나라도 빠지면 데이터베이스를 제대로 만들 수 있을까요?"
학생들이 스스로 "안 됩니다." 라고 답하도록 유도한다.

실무 연결

강사 여러분이 방금 만든 것은 사실 아주 간단한 데이터 모델입니다.

실무에서는 여기에 강사, 강의, 수강신청, 결제, 출석, 시험, 성적 등 수십 개의 Entity가 추가됩니다.

하지만 만드는 순서는 똑같습니다.
① 관리할 대상을 찾는다. ↓ Entity ==================== ② 필요한 정보를 찾는다. ↓ Attribute ==================== ③ 실제 데이터가 저장된다. ↓ Instance ==================== ④ 저장 규칙을 정한다. ↓ Domain
★★★★★ 학생들에게 "데이터 모델링은 어려운 기술이 아니라, 업무를 표로 정리하는 과정이다." 라는 인식을 심어준다.

Day1 마무리

★★★★★ 오늘 반드시 기억할 것 ① Entity → 관리 대상 ② Attribute → 관리 대상의 속성 ③ Instance → 실제 저장된 데이터 ④ Domain → Attribute가 가질 수 있는 값의 범위와 규칙
강사 오늘은 데이터베이스의 '재료'를 배웠습니다. 그런데 아직 한 가지 중요한 문제가 남아 있습니다.

학생이 두 명 모두 이름이 '김철수'라면, 데이터베이스는 어떻게 구분할까요?
학생들에게 자유롭게 답하게 한다.

예상 답변
  • 학번이 다릅니다.
  • 학생번호가 필요합니다.
  • 중복되지 않는 번호가 있어야 합니다.
강사 맞습니다. 데이터는 반드시 **유일하게 구별**할 수 있어야 합니다. 바로 그 역할을 하는 것이 다음 시간에 배울 **식별자(Identifier, Key)** 입니다.

다음 시간부터는 SQLD에서 가장 중요한 개념 중 하나인 식별자와 기본키(Primary Key)를 본격적으로 학습하겠습니다.
